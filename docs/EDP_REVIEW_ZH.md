# EDP 调研与 v0.9.0

调研日期：2026-10-09。对象：[AISkyLab EDP 官网](https://edp.aiskylab.cn/)，官方 Windows 0.9.8 安装包。安装包仅解包、检查资源及静态字符串，未安装运行或登录。

## 能力与借鉴

官网介绍的范围比器件下载工具大，主要覆盖八类能力：

| 能力 | 对本工具有价值的做法 |
| --- | --- |
| 项目、版本与交付关系 | 将器件资料关联到项目，减少散落的文件 |
| 元器件资料维护 | 搜索结果加入器件库，并关联固定的 EDA 库文件 |
| Altium 工程预览 | 从单器件预览逐步延伸到整板上下文 |
| BOM 管理与追溯 | 表格驱动匹配、核对、导出，保留数量和位号 |
| 库存管理 | 后续可关联缺料判断；当前导出工具暂不展开仓储流程 |
| 供应商与采购 | 多平台候选需要显示来源、厂商、封装及匹配依据 |
| 制造交付 | 适合更完整的项目产品，当前先做好器件准备流程 |
| 报表分析 | 提供能行动的错误与缺失资料信息 |

以上是官网声明，不能据此确认每项实际运行质量。

## 多搜索源与 Altium

官方安装包的静态信息中有立创国内/海外、华秋、Mouser、DigiKey 的平台或供应商相关标识，以及平台浏览器、资源回退、Altium workspace / bridge 相关模块。它们支持“包含多平台集成设计”的判断；实际可搜索范围、登录要求、限流和结果准确性尚未验证。部分名称也可能是兼容类型或未启用代码，不能直接当作已测通的搜索源。

类似的公开项目 [EasyEDALoader](https://github.com/expired6978/EasyEDALoader) 展示了另一条完整路径：维护固定的 Altium 库，借助 AD 端扩展把器件放进当前工程。本次借鉴操作流程，未复制其 GPL 实现代码。

Altium 的[文件库机制](https://www.altium.com/documentation/altium-designer/components-libraries/file-based-libraries)可以先安装固定路径的 SchLib / PcbLib，之后持续更新文件。本次优先实现这段可独立验证的链路。自动刷新、自动放置属于更进一步的 AD 端集成，尚未实现。

## 本次已落地

- BOM 已合并到器件库：从「导入 BOM…」进入，保留数量、位号，核对并明确确认后加入所选器件库；支持取消、重试和排除行。
- 器件库沿用原收藏及分类；按用户要求移除了独立本地搜索、备注和资料管理界面，旧收藏、设置及内部预览缓存保留。
- 操作布局：下载资源统一进入「导出…」勾选框；详细信息、打开立创页使用按钮；放大的器件图片和可换行操作；底栏任务记录居中并预留按钮空间，长路径不会挤挡。
- 原理图、三维外形、封装使用完整的大画布，通过下拉框切换并记住选择。封装按实际几何绘制焊盘、钻孔、丝印和外形；支持缩放、拖动和双击恢复。
- 原理图直接读取导出器生成的 SchLib 记录，显示 Designator、Comment、可见管脚名和编号，采用文件内的字体、字号、坐标和颜色。位号与型号避开完整符号及管脚；预览边界包含文字。字体尺寸采用 AD 文档坐标比例，参考 [AltiumSharp 的符号渲染](https://github.com/issus/AltiumSharp/blob/master/src/OriginalCircuit.Altium.Rendering.Core/SchComponentRenderer.cs)。预览使用本程序渲染器，尚未与实际 AD GUI 逐像素比对。
- 合并库选项仅在有多个可合并器件的批量导出框中显示，单器件导出及全局设置不显示。解析后再次核对器件数量，避免旧勾选状态影响单器件导出；已绑定的 AD 器件保持各自的同步路径。
- 工作区和 Description 预览默认展示 10kΩ 电阻（C25804）；Description 设置采用左侧字段选择 / 排序、右侧 AD 三栏预览。
- 每个器件库右键「绑定库文件…」选择一个 SchLib，配套同名 PcbLib；加入器件、导入 BOM 或修改 AD 导出设置后自动同步。追加和更新保留其他已有器件与附加流，使用备份、锁和中断恢复保护写入。已删除原全局固定目录设置，未绑定器件使用普通导出。

当前在线搜索仍是立创，未把静态调研中发现的供应商名称当作已接通的搜索源。KiCad 继续支持原有导出；[绑定可行性评估](KICAD_BINDING_ASSESSMENT_ZH.md)认为可实现，但本版未加入 KiCad 绑定。

## 验证范围

141 项自动测试通过，覆盖封装旋转、槽孔、凹多边形、旧设置兼容、合并导出适用范围和原理图文字边界；新增测试逐项比较预览与实际 SchLib 数据流，覆盖经典、立创、黑白及自定义配色、字体和隐藏文字。此前 Windows 测试构建已用真实 C2040 完成 AD / KiCad / PADS / STEP / OBJ 导出；把生成的单器件库作为已有库副本，加入附加元数据后，连续追加 C167747、C2040 并重复更新 C2040。两份库均保留原有器件，原器件所有流和附加元数据逐字节一致，没有重复追加。

Windows 原生 GUI 已检查浅色、深色、960×620 窗口、统一导出框和 BOM 导入框；当前构建的界面验证记录随 Windows 包提供。自动测试覆盖同名器件、关闭 3D 嵌入、混合合并导出、路径别名冲突、错误结构拒绝、字体引用、中断恢复与占用锁。

尚未在实际 Altium GUI 内执行装库、刷新、放置和设计规则检查。
