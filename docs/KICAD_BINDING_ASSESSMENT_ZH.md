# KiCad 器件库绑定可行性评估

评估日期：2026-10-09。结论：可行；建议沿用 AD 的「每个器件库一个绑定」交互，实际绑定对象为一个符号文件及配套封装、模型目录。当前体验版先完成 AD，未实现 KiCad 绑定。

## 文件结构与推荐交互

KiCad 6 起的 `.kicad_sym` 是 S 表达式文件，一个文件可含多个符号；封装则每个 `.kicad_mod` 含一个封装，库由包含这些文件的目录组成。见官方[符号库格式](https://dev-docs.kicad.org/en/file-formats/sexpr-symbol-lib/)及[封装库格式](https://dev-docs.kicad.org/en/file-formats/sexpr-footprint/)。

因此不宜把全部 KiCad 库承诺为「单个文件」。建议用户只选择 `MyParts.kicad_sym`，绑定对话框显示配套的 `MyParts.pretty/` 和 `MyParts.3dshapes/`，允许确认或调整路径。按 C 编号给符号、封装和模型建立稳定标识；符号内的封装字段引用库昵称与封装名，模型使用可迁移路径。

## 现有基础

本项目已有 KiCad 单器件及多器件合并写出，符号、封装、3D 引用的生成可以复用。当前写入器面向生成完整文件，不负责读取、合并用户现有符号库。因此自动绑定仍需要独立的增量更新层；直接调用完整写入器会覆盖已有内容。

## 需要实现和验证的内容

1. 解析 S 表达式，保留未修改符号、未知字段及版本信息；识别继承关系，不用正则或括号计数拼接现有库。
2. 使用稳定 C 编号去重，保存与显示原始型号，正确更新符号到封装、封装到模型的引用。
3. 对符号文件、封装文件及模型实施冲突检查、文件锁、备份和可恢复事务。只改本工具管理的器件，保留用户已有项。
4. 测试已有库追加、重复更新、同名不同 C 编号、没有 3D、Unicode 路径、只读/占用、更新中断和不同格式版本。
5. 在实际 KiCad 符号编辑器与 PCB 编辑器内核对装库、放置、封装关联和 3D 显示。

库文件同步与 KiCad 库表注册是两个动作。首版宜引导用户安装固定库一次；若以后提供自动注册，需要明确项目库或全局库的范围，并保留已有库表设置。绑定文件本身不代表已经把器件放进当前工程。

以上可行性和实现建议基于官方格式及当前代码评估；尚未进行 KiCad 绑定原型或实际应用验收。
